[57] Evil Twin Attack เป็นรูปแบบหนึ่งของการโจมตีในเครือข่ายไร้สาย (Wireless Network Attack) ที่ผู้โจมตีสร้าง Access Point (AP) ปลอม โดยตั้งค่า SSID (ชื่อเครือข่าย) ให้เหมือนหรือคล้ายกับเครือข่าย Wi-Fi ที่ถูกต้อง เพื่อหลอกให้ผู้ใช้งานเชื่อมต่อโดยไม่รู้ตัว เมื่อผู้ใช้เชื่อมต่อกับ Access Point ปลอมดังกล่าว ผู้โจมตีสามารถทำหน้าที่เป็นตัวกลาง (Man-in-the-Middle) เพื่อดักจับ วิเคราะห์ หรือแก้ไขข้อมูลที่รับส่งผ่านเครือข่ายได้
[58] ลักษณะสำคัญของ Evil Twin คือความสามารถในการเลียนแบบเครือข่ายจริงได้อย่างแนบเนียน โดยผู้โจมตีสามารถตั้งค่า SSID ให้ตรงกับเครือข่ายเป้าหมาย และอาจปรับค่าต่าง ๆ เช่น Channel หรือกำลังส่งสัญญาณ (Signal Strength) เพื่อให้ Access Point ปลอมมีความน่าสนใจและมีโอกาสที่อุปกรณ์ของผู้ใช้จะเลือกเชื่อมต่อมากขึ้น โดยเฉพาะในกรณีที่อุปกรณ์ตั้งค่าให้เชื่อมต่ออัตโนมัติ (Auto-connect)
[59] การโจมตี Evil Twin มักเกิดขึ้นร่วมกับเทคนิคอื่น เช่น Deauthentication Attack ซึ่งเป็นการส่งเฟรมเพื่อบังคับให้ผู้ใช้หลุดจากเครือข่าย Wi-Fi จริง เมื่อผู้ใช้ถูกตัดการเชื่อมต่อ อุปกรณ์จะพยายามเชื่อมต่อใหม่ และมีโอกาสเลือกเชื่อมต่อกับ Access Point ปลอมที่มีสัญญาณแรงกว่า ส่งผลให้ผู้ใช้ตกเป็นเหยื่อของการโจมตีโดยไม่รู้ตัว
[60] Wifi Management Frame
[61] เฟรมประเภท Wi-Fi Management Frame เป็นส่วนหนึ่งของมาตรฐาน IEEE 802.11 ที่ใช้สำหรับควบคุมและจัดการการเชื่อมต่อระหว่างอุปกรณ์ลูกข่าย (client) และจุดเชื่อมต่อ (Access Point: AP) โดยไม่ได้ใช้ส่งข้อมูลผู้ใช้โดยตรง หน้าที่หลักของเฟรมประเภทนี้คือการสร้าง (establish), รักษา (maintain) และยุติ (terminate) การเชื่อมต่อในเครือข่ายไร้สาย ตัวอย่างของ management frame ได้แก่ beacon frame ที่ AP ใช้ประกาศตัวตนและพารามิเตอร์ของเครือข่าย (เช่น SSID, channel, security), probe request/response สำหรับการค้นหาเครือข่าย, authentication และ association frame สำหรับการเข้าร่วมเครือข่าย รวมถึง deauthentication และ disassociation frame สำหรับตัดการเชื่อมต่อ เนื่องจากเฟรมเหล่านี้มีบทบาทสำคัญในกระบวนการควบคุมเครือข่าย และในบางกรณีไม่ได้ถูกเข้ารหัส (โดยเฉพาะในมาตรฐานเก่า) จึงกลายเป็นจุดอ่อนที่ผู้โจมตีสามารถนำไปใช้ เช่น การปลอม beacon หรือส่ง deauth frame เพื่อโจมตีแบบ Evil Twin หรือ DoS ได้
[62] Beacon Frame เป็นเฟรมย่อยของ Wi-Fi Management Frame ที่ Access Point ส่งออกมาเป็นระยะอย่างสม่ำเสมอ (periodic broadcast) เพื่อประกาศการมีอยู่ของเครือข่ายและให้ข้อมูลพารามิเตอร์ที่จำเป็น เช่น SSID, BSSID, channel, supported data rates และรูปแบบความปลอดภัย (security capabilities) โดย client จะใช้ข้อมูลจาก beacon ในการค้นหาและตัดสินใจเลือกเชื่อมต่อกับเครือข่าย ตามทฤษฎี beacon เป็นกลไกสำคัญที่ทำให้เครือข่ายไร้สายสามารถถูกค้นพบได้โดยอัตโนมัติ อย่างไรก็ตาม ความที่ beacon ถูก broadcast และมักไม่ถูกเข้ารหัส ทำให้ผู้โจมตีสามารถสร้าง beacon ปลอมเพื่อเลียนแบบเครือข่ายจริง (เช่น Evil Twin) และหลอกให้ผู้ใช้เชื่อมต่อเข้ากับเครือข่ายปลอมได้
[63] Deauthentication Frame (Deauth) เป็นเฟรมย่อยของ Wi-Fi Management Frame ที่ใช้สำหรับยุติการยืนยันตัวตน (authentication) ระหว่าง client กับ Access Point โดยตรง เมื่อมีการส่งเฟรมนี้ หมายความว่าความสัมพันธ์ด้านความปลอดภัยถูกตัดขาดทันที ทำให้ client ต้องเริ่มกระบวนการเชื่อมต่อใหม่ทั้งหมด (ตั้งแต่ authentication และ association) ตามทฤษฎีแล้ว AP จะส่ง deauth เมื่อพบพฤติกรรมผิดปกติ เช่น session หมดอายุ หรือมีปัญหาด้านความปลอดภัย อย่างไรก็ตาม เนื่องจากในหลายกรณีเฟรมนี้ไม่ได้ถูกป้องกันอย่างเข้มงวด ผู้โจมตีสามารถปลอมแปลง deauth frame เพื่อบังคับให้ client หลุดจากเครือข่าย (deauthentication attack) ซึ่งมักถูกใช้เป็นขั้นตอนหนึ่งของการโจมตีแบบ Evil Twin หรือ Denial of Service (DoS)
[64] Probe frame เป็นเฟรมย่อยของ Wi-Fi Management Frame ที่เกี่ยวข้องกับกระบวนการ “ค้นหาเครือข่าย” (network discovery) โดย client จะส่ง Probe Request เพื่อถามหาเครือข่ายที่ต้องการ (อาจระบุ SSID เฉพาะ หรือ broadcast เพื่อถามทุกเครือข่าย) และ Access Point ที่ตรงเงื่อนไขจะตอบกลับด้วย Probe Response ซึ่งมีข้อมูลลักษณะเดียวกับ beacon เช่น SSID, channel, security และ capability ต่าง ๆ ตามทฤษฎี กลไกนี้ช่วยให้ client สามารถค้นหาเครือข่ายได้รวดเร็วกว่าแบบ passive (ฟัง beacon อย่างเดียว) อย่างไรก็ตาม probe frame ก็เป็นช่องทางโจมตีได้ เช่นใน KARMA attack ที่ attacker ดัก probe request แล้วตอบกลับปลอมเพื่อหลอกให้ client เชื่อว่าเครือข่ายที่ต้องการมีอยู่จริง
[65] Association frame เป็นเฟรมที่ใช้ในขั้นตอน “การเข้าร่วมเครือข่าย” หลังจาก client ผ่าน authentication แล้ว โดย client จะส่ง Association Request ไปยัง Access Point เพื่อขอเชื่อมต่ออย่างเป็นทางการ พร้อมระบุความสามารถของตนเอง (เช่น supported data rate, capability) และ AP จะตอบกลับด้วย Association Response เพื่อยืนยันหรือปฏิเสธการเชื่อมต่อ หากสำเร็จ client จะได้รับ Association ID (AID) และสามารถเริ่มรับ-ส่งข้อมูลในเครือข่ายได้ ตามทฤษฎี ขั้นตอนนี้เป็นจุดที่กำหนดความสัมพันธ์เชิงโครงสร้างระหว่าง client กับ AP และเป็นเงื่อนไขสำคัญก่อนเข้าสู่ data communication จริง ๆ นอกจากนี้ หาก attacker แทรกแซงในขั้นตอนนี้ (เช่น ผ่าน Evil Twin) ก็สามารถทำให้ client ไปเชื่อมกับ AP ปลอมแทนของจริงได้
